# Audit: is aegraph-ui fit for a company's internal use? (2026-09-29)

*Written against aegraph-ui's hosted edition (sign-in, server functions), which this edition removes.*

Five passes over the tree: security, reliability (data safety), code quality and engineering process, company
readiness (deployment, identity, licensing), and UX / accessibility / performance. Two sessions audited it in
parallel and split the fixes; both sets are merged. Each finding has a status: **fixed** (merged to `main`),
**open** (backlog), or **decision** (the owner's call, not a code change).

## Verdict

**Fit for a small internal pilot now, run locally or behind the company's own sign-in, after the fixes below.
It is not yet fit for a rollout across a company.** The engineering is careful. Untrusted data is treated as data:
sandboxed scripts, a QuickJS realm for constraint rules, sanitised diagrams, bounded decompression, the
external-services switch, and guards that keep user data out of git. The test suite is large: 314 files, 2,159 tests after the fixes.
What holds back a wider rollout is less the code than what surrounds it:

- **One maintainer.** Almost every commit is written by an agent, with no second reviewer.
- **No releases.** There are no tags or changelog, and the version is 0.0.0.
- **Identity and deployment.** Sign-in is GitHub or Google only, and the functions are Vercel's.
- **No sharing model.** The app is single-user, and it keeps no audit log.

On data loss: every defect found that could silently lose or corrupt a user's work is fixed — the overlay that undid
bulk writes, compaction that cleared before it rewrote, another tab's bulk write wiping this tab's edits and open
project, a load failure that saved nothing without saying so, boot migrations that retyped data by name. What is
left is written below as open items, none of them silent.

## Decisions for the owner

1. **Bridge defaults.** The hosted origin is now a setting (`AEGRAPH_HOSTED_ORIGIN`, empty for none) and the tab
   follows probes to loopback only, but by default the bridge still trusts aegraph.dev and any loopback origin, and the
   token is optional. For a company: set `AEGRAPH_HOSTED_ORIGIN` to the company's deployment (or empty) and require
   `AEGRAPH_BRIDGE_TOKEN` — slightly more setup per developer. A tab also does not yet prove the server it connects to is
   genuine, which matters on shared multi-user hosts (an HMAC challenge would close it).

4. **Identity.** Sign-in is GitHub or Google through Supabase. A company will ask for SAML/OIDC SSO. Supabase offers
   SAML on paid plans, or the app can be put behind the company's own proxy.
5. **Releases.** Tag versions, keep a changelog, protect `main` (required CI, one human review). The last point is
   the single biggest step for a company's confidence: today nothing stops an unreviewed change reaching the deploy.
6. **Hosting.** `api/*` are Vercel functions. Either state that as a requirement, or wrap them for Node, which the
   headless server shows is feasible.

## Backlog (open, by priority)

1. **Tests of the UI.** There are no DOM or component tests: every test is of logic or of tools. Add a few for:
   - the dialogs, including focus;
   - the Load dialog;
   - the history restore;
   - one smoke path per page.
2. **Lint warnings.** They are not enforced; make `--max-warnings` a ratchet.
3. **Type-checking.** `strict` is implicit (TypeScript 6's default); state it. `mcp/*.mjs` (3.7k lines) is untyped:
   add `// @ts-check` or `checkJs`.
4. **Transactions.** A store transaction that throws does not roll back; only the events are batched.
5. **Concurrent edits.** Editors are last-writer-wins across tabs.
6. **The CSP is broad.** `'unsafe-eval'` is there for Pyodide; see SECURITY.md. Consider loading Python only on a route
   that serves its own, narrower policy.
7. **Headless `export_file`.** It overwrites any file under its root without asking.
8. **The initial payload** is about 870 KB gzip:
   - split the Unigraph engine, the globe and the Python and script editors out of the first load;
   - ELK is bundled three times;
   - six layout engines ship.
9. **Dead files**, left from the sigma and three.js renderers.
10. **Licences.** The inventory lacks Pyodide's packages and the ONNX models.
11. **Layout.** There is no mobile layout and no dark mode. Neither matters for a desktop internal tool, but both are
    asked about.
12. **Native dialogs.** `window.confirm` / `prompt` survive in the Constraints panel, the dataset grid and the Scripts
    page; move them to `ConfirmDialog`.
13. **Sign-in and the allow list** take exact emails from GitHub or Google only: add an allowed-domain rule and more
    providers (Azure, Keycloak, SAML through Supabase) — see decision 4.
14. *[Redacted in the public edition: notes on the hosted site's configuration.]*
15. **Persistence follow-ups.**
    - A replace (import in replace mode) that crashes between its first write and its last transaction leaves old and
      new side by side; nothing is lost, but the replace is incomplete.
    - A remote change now arrives as upserts, so a tab's autosave may commit changes the other tab also commits.
    - A bulk write elsewhere still makes every other tab read the whole database.
    - The stash room check does not count the space clearing would free, so a restore over a big Library may be
      refused (the message says to clear first).
    - Firefox shows its storage-persistence prompt; the app asks again on each visit until it is answered.
16. **Bridge errors.** Tool errors coming back from the tab reach Claude Code unframed (results are framed).
17. **Accessibility beyond this pass.** Table headers as buttons with `aria-sort` and row focus; tab strips as
    `tablist`; the dataset grid's canvas has no accessibility tree; GPU context loss is not recovered.
18. **CI red for three days went unnoticed.** Treat a red `main` as stop-the-line, and add a nightly headless smoke job
    (`mcp/smoke/*` today runs by hand).

## How this was checked

- Type-check, `npm run lint`, and the full `npx vitest run`: 299 files, 2,038 tests (first pass); after the second
  pass `npx tsc -b --noEmit` (with `api/`), lint (exit 0), `npx vitest run --no-file-parallelism`: 314 files, 2,159
  tests, and a production build with the ONNX files present.
- Every fix in the second pass has a test that fails on the code before it (checked by swapping the old file in).
- In a browser (a scratch profile, a private dev server): a 100k-entity import survives a reload; a bulk rewrite over
  a small edit reloads as the bulk version; the compaction a repeated 100k rewrite triggers loses nothing; a
  3,000-entity write in a second same-origin document leaves the first one's open project and its own edit in place;
  refused writes show the notice and Try again saves them; eleven pages open with no error boundary and a per-page title.
- The persistence fixes each have a test in `core/entity/__tests__/persistence.test.ts`. The overlay test fails with
  the fix taken out.
- The CI build was run in a clean worktree, with the vendor step, the sandbox bundles and the ONNX files present.
- Contrast was computed with the WCAG 2.1 relative-luminance formula against `--bg`, `--surface` and `--surface-2`.
