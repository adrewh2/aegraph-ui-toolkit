# Audit — logic, product definition, UI harmony

*2026-09-13. 44k lines of TypeScript, 124 commits, 273 tests. Read: the store, persistence, projects, exchange, the assistant/MCP tools, the page shells, and the CSS. Not read line by line: the explorer renderers, the diagram converters, the media apps' internals.*

Each finding says whether it was **fixed in this pass** (commit `b7efd9b` and the two before it) or is **open**, and why it matters. Ranked within each section.

## 1. Logic

### Fixed

| # | Finding | Where | Why it mattered |
| --- | --- | --- | --- |
| L1 | **Deleting while a project was open left dangling relationships.** `store.remove` cascaded through the *scoped* `relationshipsOf`, so links from outside the project to the deleted entity survived it. | `core/entity/store.ts` | Every graph view filters dangling edges defensively, so it showed up as counts that never added up and `danglingRelationships()` growing over time. |
| L2 | **Tag rename/delete only touched the open project.** `renameTag`/`deleteTag` used the scoped `withTag`, so the same tag could end up spelled two ways across projects. | `core/entity/store.ts` | Tags are Library-wide by definition (P4 in the projects proposal). |
| L3 | **Re-importing a diagram or graph replaced only the in-scope half of its earlier run.** Both `mapping.ts` files found the previous run's entities with the scoped `store.all()`. | `core/diagrams/mapping.ts`, `core/exchange/graph/mapping.ts` | Duplicate nodes after re-running an import with a different project open. |
| L4 | **Deleting a project "with exclusive entities" kept their relationships.** `cascade: false`. | `core/projects/project.ts` | Same dangling-link class as L1. |
| L5 | **A project's stashed UI state was never cleared on delete.** `clearStashedUiState` existed and had no caller. | `features/projects/ProjectsView.tsx`, `assistant/projectTools.ts` | localStorage leak; a re-created project with the same id would inherit stale explorer positions. |
| L6 | **Two persistence loads raced** (React dev double-effect); the second refilled the store after the first caller had scoped it, marking the whole Library with the open project. Fixed earlier this session (`21864dd`); recorded here because it is the class of bug to watch for: *anything that clears and refills the store must not run under a scope.* `clear()` now drops the scope. | `core/entity/persistence.ts`, `store.ts` | Silent data corruption (marks on 14 seed entities, found by accident). |
| L7 | **Deep links into the Entities page were bounced to `/entities`** by the pane host restoring its last tab under the double effect. | `features/workstation/WorkstationView.tsx` | Every tool that navigates (`inspect`, `open`, `Open in Entities`) landed on the wrong table. |
| L8 | **A property defined after a table's column choice was saved stayed hidden.** | `features/resources/EntityTable.tsx` | Defining a property "for every Person" produced no visible column. |
| L9 | **Every `TypeRegistry` walked the whole scope to count types**, once per consumer per store change (`useTypeRegistry` builds a registry per component). Cached per version now. | `core/entity/store.ts` | On a large imported project, tens of full walks per keystroke. Performance is a stated priority. |

## 4. Code quality notes

Done in this pass (commits `599432b`, `1cc1d8c`, `2db777a`, and the smoke commit):

- `features/assistant/tools.ts` (2,075 lines, ~45 tools) is now the host contract plus a list; the tools live one file per domain — `appTools`, `documentTools`, `entityTools`, `mediaTools`, `graphTools`, beside `moreTools`, `plotTools`, `projectTools` — with `toolkit.ts` for what they share. Manifest order unchanged.
- `EntityBrowser.tsx`: URL state (`useBrowserUrl`), the row menu (`rowMenu.ts`) and the table's column preferences (`useTablePrefs`) are their own modules with explicit inputs.
- `store.library` is the one way to read past the scope (same read API, separate caches); the earlier `libraryAll` / `queryLibrary` / `relationshipsOf(…, scoped)` trio is gone.
- `npm run smoke` (`mcp/smoke.mjs` over `mcp/drive.mjs`): a fresh profile creates a project, loads a demo, relaunches on a deep link, sets typed properties, saves and reopens a bundle — 16 checks, including the two that the load-race and deep-link bugs would fail. Needs the dev server on :5199 and Chrome; ~40 s.

Still worth doing:

- `EntityTable.tsx` (741) still mixes filtering/sorting, editing, menus and rendering; `rows` (filter + sort) and the cell renderer could follow the same extraction.
- Views are thin on unit tests; the smoke suite is the integration net. A CI job that starts `vite` and runs `npm run smoke` would make it count.
- `.env.local` local-demo path hack and the ChatGPT pipeline follow-ups are in `docs/followups.md`; the projects and navigation proposals in `docs/proposals/`.
