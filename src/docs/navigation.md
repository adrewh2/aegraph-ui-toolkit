# Getting around

The app is one Library, browsed from several pages; a **project** narrows every page to one scope ([Projects](/docs/projects)). This page is the map of those pages — where each thing is, what the tables and inspectors do everywhere, and the keys.

## The sidebar

| Page | What it is |
| --- | --- |
| **Dashboard** | Counts by category, relationships and tags, and what you touched most recently, under a greeting for the time of day. |
| **Workstation** | Split panes hosting any page as tabs; saved arrangements (below). |
| **Chats** | The open project's chats with the assistant as a page: the chats (open, recorded, imported) on the left, the conversation in the middle, and the chat's artifacts — the documents, diagrams, maps, scenes and entities it made — open as tabs on the right, Unigraph among them ([Assistant & MCP](/docs/assistant#the-chats-page)). |
| **Entities** | The table of everything: by category (Resources, Knowledge, Project), by type, by tag, by text; relationships, types and tags as sections of the same page. |
| **Ontology** | The vocabulary: **Schema** (every type and relationship type with its properties, parents and the type pairs it joins, downloadable as JSON), **Network** (types as nodes, relationship patterns as links), **Tags** (the tag matrix), **Claims** (findings kept with evidence, named communities), **Constraints** (the rules every write must satisfy — [Constraints](/docs/constraints)). A type's own page lists its properties, relationships and instances. A type's swatch, in the Schema list or on its page, sets the colour it is drawn in everywhere — tables, chips, the graph — and *Automatic* puts it back to the colour derived from its name; a tag's colour is the **Colour** column in Entities › Tags. |
| **Resources** | The applets: Documents, Diagrams, Images, Videos, Audio, Maps ([Documents & media](/docs/resources), [Diagrams](/docs/diagrams), [Maps](/docs/maps)). |
| **Unigraph** | The graph explorer: filter, layout, style, scenes, sessions as tabs, in 2D or 3D on one engine built for graphs up to a million nodes ([Unigraph](/docs/explorer), [The engine](/docs/explorer#the-engine)). |
| **Insights** | Analyses that return ranked findings ([Insights](/docs/insights)). |
| **Analytics** | Making and keeping, in the order the work flows — scene → script → dataset → chart: **Scenes** (one saved scene or one chart drawn on its own — what a script, a diagram or a graph session leave behind. Scenes are a family: a *scene* arranged by hand or captured from a diagram, a *script scene* a script drew, and a *graph scene*, a filter + layout + style composition that the list shows and its page opens — a *Unigraph scene* on Unigraph, where Save and Save as… in the toolbar make them; [Diagrams](/docs/diagrams), [Unigraph](/docs/explorer)), **Scripts** (code over the dataset — figures, tables, scenes; [Scripts](/docs/scripts)), **Datasets** (the tables scripts return, kept as entities and edited in a grid; [Datasets](/docs/datasets)), **Charts** (a question over entity fields answered as a figure, no code; [Charts](/docs/plots)). The Scenes and Charts lists are galleries: each card carries a picture of what it opens — the view as it was saved, or one drawn from the scene's positions or the chart's marks, which is how a scene or chart made over MCP or by the headless engine gets one too. |
| **Projects dialog** | Not a row but a dialog, from the project control above the rows (or `/new`): opening a project, the demos, files in and out, generated graphs, ChatGPT and Spotify imports, where projects are stored ([Import & export](/docs/exchange)). |
| **Documentation** | These pages, searchable; the assistant reads them too — including [Privacy & security](/docs/privacy): where your work lives, what reaches the network and when. |
| **Assistant** · **Claude Code** | The chat panel (`⌘J`) and the bridge that lets Claude Code drive the app ([Assistant & MCP](/docs/assistant)). |
| **Settings** | The button at the foot of the sidebar: your settings (below), and **This browser** — stashing, restoring and clearing what aegraph keeps in this browser ([This browser](/docs/navigation#this-browser)). |

A deployment can leave Maps, the globe, Videos or Audio out of its build: then their rows are not in the sidebar, their addresses open a page saying the feature is turned off on this deployment, and the places, videos and tracks in your projects stay in the Entities table ([Privacy & security](/docs/privacy#running-it-for-an-organisation)).

Each page names the browser tab it is in — *Documents · aegraph*, *Unigraph · aegraph* — by the name its row has here, so tabs, the browser's history and a screen reader tell the pages apart; an address deeper in a page (a document, a type, a project's history) takes the name of the page it sits in.

The project control at the top of the sidebar switches projects, saves a bundle, shows unsaved changes, and opens a project's Overview · Changes · History · Settings.

**When the rows do not fit.** On a short window the rows scroll between the search box and Documentation, which stay put, and the scrollbar stays in view whenever there is more below, so no row is hidden without a sign of it.

**The numbers beside the rows.** **Chats** carries how many chats the Chats page lists — the open project's conversations, recorded or imported, and its chats open in this browser that are not recorded yet, each counted once (every chat, with no project open). **Entities** carries how many entities the open project holds, relationships aside. Resources and Analytics carry how many of each kind there are — 21 documents, 15 scenes, 25 charts — and the group itself carries the total, counted in the open project, so the number agrees with the page the row opens. Scripts count their kinds together (a filter, layout, style, scene or constraint script is still a script) and Scenes the whole family (a scene arranged by hand, one a script drew, a Unigraph composition). A kind with nothing in it shows no number rather than a zero. The saved thing itself says how much it holds where it is listed: a chart its rows, a graph scene its nodes and edges, a script its lines.

**Settings.** The button at the foot of the sidebar reads **Settings** and opens the settings menu. There is no account and nothing to sign in to: everything is kept in this browser. The menu's **This browser** link opens `/browser` ([below](/docs/navigation#this-browser)), which stashes what aegraph keeps in the browser, restores a stash, and clears it all to see the app as a new user does. Then your **settings**, kept in this browser. **Third-party services** is the one switch over everything that leaves your machine — map tiles, place search, Wikipedia, search by meaning, the YouTube and Spotify players, linked-data import, embedded web pages. It is on; turning it off is offline mode, where those features refuse rather than call out and the map draws your places on plain ground ([Privacy & security](/docs/privacy)). **Developer tools** shows the tools for working on aegraph itself, which today means the GPU graph view's *Benchmark* menu. Over MCP the `account` tool reads the same, sets the settings, and stashes, restores and clears this browser.

**Theme** picks how the app looks: *Paper* (the warm off-white it has always had), *Dark*, *Midnight* (a cool blue-black) or *High contrast* (black on white with strong borders) — or *System*, the default, which shows Paper or Dark as your operating system is set and follows it when it changes. The theme covers everything, the graph canvas, charts and maps included (dark themes darken the map tiles); it applies at once, and is in place before the page draws on the next visit.

**Folded to the rail.** `⌘B` folds the sidebar to a column of icons; the **ae** mark at the top unfolds it again (the panel icon appears under the pointer). Unigraph's *Full view* folds it too, and unfolds it on the way out when it was the one that folded it. Hovering an icon names it straight away, beside it. A group — Resources, Analytics — opens as a menu to the right of its icon with its pages and their counts: hover to see it, click the icon to keep it open (a group has no page of its own, so clicking it never leaves the page you are on), Escape or a click elsewhere to dismiss it. Unfolded, a group's row folds and unfolds its pages, and says whether it is open to a screen reader.

## This browser

**This browser** (`/browser`, from the settings menu at the foot of the sidebar) is about everything aegraph keeps in this browser: every IndexedDB database (the Library and every project in it, version history, held graph positions, previews, settings) and localStorage (chats, what each page last showed, the bridge's link to Claude Code). **Stash now** copies all of it — every database with its version, its stores and every record, and localStorage — into a **stash**, named as you like, kept in this browser beside it; the list below shows each with when it was taken and how much it holds, **Restore…** puts the browser back as it was then, and the bin deletes one. **Clear this browser…** deletes everything but the stashes — sessionStorage and Cache Storage too — and the app loads as a first visit, the way a new user sees it. With **Stash what is here first** ticked (the default) clearing and restoring both take a stash of the browser as it is before it goes, so neither loses anything: stash, clear, look at aegraph as a newcomer, restore. Unticked, anything not stashed, exported or published is gone for good. Both ask first, and the question says what goes and what stays. A stash leaves your **keys** out — the Claude key, the OpenAI key, the Spotify sign-in and the bridge's address — unless **Include keys in stashes** is ticked, because a stash is a plain copy that clearing never deletes; clearing deletes the keys, and a restore keeps the keys this browser has now unless the stash holds its own (the list marks such a stash *holds keys*). A browser keeps up to ten stashes: past that, **Stash now** asks you to delete one first, and a stash the browser has no room for is refused before anything is copied. Stashes are in this browser only: another browser does not see them, and deleting the site's data in the browser's own settings deletes them with the rest — export a project to keep it anywhere else. Clearing and restoring happen at the start of the next load, before the app opens a database — done from inside the running app, its own open connections would hold the databases and its save-on-leave would write state straight back — so close any other aegraph tab first (the page says so if one still holds a database, and finishes once it closes). A restore is whole or still to do: it first checks that the stash fits in the room the browser has, and when it does not it changes nothing and says how much is needed (clearing the browser first, which keeps the stashes, usually makes the room); once started, it stops rather than write the stash over a database that would not be deleted, and until the last record is back the next load takes the restore up again instead of starting the app on part of a browser — the page offers **Try again** or **Open aegraph as it is**. Over MCP it is `account`: `stash_browser {name}`, `stashes`, `restore_stash {id, stash_first}` (stashes first unless `stash_first` is false), `delete_stash {id}`, and `reset_browser {stash_first}`; restoring, deleting and clearing ask the user the same, and the tab reloads just after answering — the tools go quiet until Claude Code is connected again.

## ⌘K — one box for everything

`⌘K` — or the search box at the top of the sidebar, which is the same thing — opens the command palette: type a few words and it lists **recent** things, **actions** (open a page, run the layout, fit the graph, turn the graph view into a table, ask the assistant, talk to it), entities **by name**, tag or description, entities matched **in text** (a document's body, a transcript, a page — with the line that matched, the words marked, and the field it was in), an **all N matches in the Entities table** row for the full set, saved **views**, **tags**, **types**, **projects**, Insights **findings** and the **documentation**'s sections, each with a hint of what it is. Every word must occur; "quoted words" match as a phrase. `Enter` opens (with nothing listed, the Entities table with the same words); on an entity, `⌘Enter` shows it in the graph. The list remembers what you chose. The typing stays in the box while `↑` `↓` move through the results, and a screen reader hears the result each move lands on; `Esc` closes the palette and puts the focus back where it was.

## Tables

Every table in the app — Entities, the map's list, a graph view as a table, relationships, types, tags — is the same component, so it works the same way:

- **Search** all columns at once; **filter** any column by text, or by ticking values (types, tags, properties with options); a **Types** menu when rows are of several types, grouped under their kind (Locations › Sight, Hotel…; Areas › Island), a whole kind a tick. A filter in force says so, and *Filters* keeps named sets per table; the last state is remembered per table and per project.
- **Sort** by a header; drag headers to reorder; **Columns** shows and hides them, widths drag. A type can say how it reads by default — which columns first, which hidden, the sort — in its definition (`table`, set by the `table_layout` tool or a bundle; [file format](/docs/spec)), and a subtype reads as its kind: *Area · Island*.
- **Select** by click, `⌘`-click, `⇧`-click, checkbox or a marquee drag; `⌘A` all, `Esc` none, `↵` opens, `⌫` deletes (with confirmation). Selected rows drive the toolbar: *Related to*, *Set property* (bulk), *Projects* (add to / remove from), *Graph* (the selection as a view), *Chart*, *Export*, *Delete*.
- **Read only.** A table of entities is for reading, sorting and picking: a double-click opens the row, and nothing is changed by a click in a cell. A row is changed from its right-click menu — **Rename…** (the name alone) or **Edit…** (a wide dialog: the name, the description and the tags on the left, every property the type declares on the right, each with the input its kind calls for, a filter when there are many; ⌘↵ saves) — and saved in one write when you press Save, so an edit costs the same in a project of a hundred entities or a million. The inspector edits too. The **Types** and **Tags** tables, whose rows are definitions rather than entities, still edit a cell by double-click.
- **Right-click** any row — or a node or an edge in Unigraph, or a pin, a path, an area or a note on a map: **the same menu wherever an entity is**, led by what that view can do with it (a table's *Open*; the graph's *Select neighbours*, *Focus*, *Path from here*, *Pin*, *Hide*; the map's *Show on map*, *Details*, *Pin note here*), then always, in this order: *Rename…*, *Edit…*, *Annotate…*, *Link to…*, related entities, *Open in Entities*, *Ask about this*, *Chart…*, *Set property…*, projects, the view's tag filters, *Copy ID*, *Copy as JSON*, and *Delete…* (with confirmation). A right-click on empty map is still the map's own menu (add a location, start a path).
- Exports of the visible or selected rows as `.ae.json` or CSV; pages of 25 to 1,000 rows, or **All** — every row, up to 5,000 on a page (past that, pages of 5,000: the table draws every row of a page, and five thousand stays under a second).

## Selected text: Insights

Select words anywhere you read — a document, a PDF, a chat, these pages — and right-click them. The app's menu opens in place of the browser's: **Insights**, **Ask about this**, **Search everything**, and **Copy** (with **Cut** and **Paste** where the text is editable, as in a document you are writing). Shift + right-click gives the browser's own menu; with nothing selected, or on a row or the graph, which have menus of their own, nothing changes.

**Insights** opens a card under the words with what in the open project they touch:

- **Named here** — entities whose name (or an alias, `data.aliases`) appears in the words as whole words, longest names first: select a paragraph and every person, place and thing it names is listed. Select a single name and entities whose names contain it come too ("Ada" finds *Ada Lovelace*).
- **Tags** — tags whose name appears, or the last part of one (`topic:engines` for "engines"), with how many entities carry each; a tag opens them in the Entities table.
- **Mentioned in** — for a selection of six words or fewer, entities whose own text holds it as a phrase: the notes, documents and transcripts that talk about it.

Case, accents and punctuation do not matter, and common words and anything shorter than three letters are never taken for a name. The document you are reading is left out of its own insights. A row opens the entity; **Show all in Entities** puts them all in the table; **Ask the assistant** hands the passage to the chat. **Back** from where a row took you returns to the page with the same words selected and the card open again, so you can go through its entities one by one; a card you closed yourself stays closed. Over MCP the same answer is `text_insights {text, exclude?}`.

## The inspector

Selecting a row opens the inspector on the right (every page uses the same one): **Fields** (every property, editable, typed by the ontology), **Annotations**, **Relationships** (add, remove, follow — with counts by type), **JSON**, and validation issues. A map's inspector is the live map; a place's shows it on a small one; a document's is its info panel. *Open in its page* leads to the applet; the breadcrumb leads back.

## The Workstation

**A section is a set of inner tabs.** Documents, Diagrams, Images, Videos, Audio, Maps, Scenes, Scripts, Datasets, Charts, Ontology and Projects each open on their **List** — the section's index, as an inner tab at the front that cannot be closed. Whatever you open from a list — a document, a diagram, a map, a type, a chart, a scene (a graph scene opens its Unigraph view right there, in the Scenes tab) — opens as a tab of its own beside it, named after it, with a ✕ to close it when you are done; opening one that is already open brings its tab forward instead of a second. Going back to the list — the page's own breadcrumb, a link, the section in the sidebar while you are in it — brings the List tab forward and leaves the open tabs where they are; arriving at the section from elsewhere finds the tab you left in front. Tabs split and drag as in the Workstation, and the address bar follows the tab in front, so a link or a refresh lands on the same one.

**Workstation** is iTerm-style panes: split any pane right (`⌘D`) or down (`⌘⇧D`), drag the gutters, close (`⌘⇧W`); each pane holds tabs (`⌘⇧]` / `⌘⇧[` to move between them, `⌥⌘←/→` between panes), and each tab is any page in the app, running under its own address — so a map, the document about it, the tickets folder and a chart sit side by side, and the browser's URL stays put. Tabs drag between panes. It is the front door: aegraph opens on the Workstation. A first visit opens the **aegraph-ui system map** demo — the app's own architecture as an ontology and its graph — as its project on one pane with one tab: its whole graph in **Unigraph · 3D**, unfiltered, opening on positions settled when the demo was built — so the first frame is the finished picture — with the force simulation carrying on from there. A new project and a cleared workstation start from **Chats** in front and the project's graph in **Unigraph · 3D** behind it, while the **Dashboard** is a click away in the sidebar. Arrangements persist locally and can be saved as `workstation` entities — a project's bundle carries one, so it reopens as it was saved; templates seed common layouts. The **Entities** and **Unigraph** pages are pane hosts themselves: a filtered view (*Related entities*, a chart's pick) opens as a tab beside the one you came from.

**By keyboard.** Every control shows a ring when the keyboard reaches it (a click shows none). A dialog — and the `⌘K` palette — takes the keyboard when it opens: the focus moves into it, `Tab` and `⇧Tab` go round its fields and buttons without leaving it, and when it closes the focus is back on what opened it. A dropdown opens as a menu of its choices, the current one ticked and first under the keys: `↑` `↓` or a letter to move, `Enter` to choose, `Esc` to leave it as it was. A short message in the corner (*Saved*, *Copied*) is read out by a screen reader as it appears.

**Less motion.** When your system asks for reduced motion (*Reduce motion* in macOS or iOS accessibility settings, *Show animations* off in Windows), the app keeps still: panels, menus and transitions appear at once, the Unigraph camera jumps to where a fit, a click in a table or a tool sends it instead of gliding there, and the Workstation's tab strip and the jumps to a finding or a heading land without scrolling through the way.

## Getting back

Every page and every entity has an address (`/entities?category=knowledge&type=sight&sel=<id>`, `/documents/<id>`, `/maps/<id>`, `/unigraph/2d?scene=<id>`, `/diagrams/<id>`, `/analytics/charts?plot=<id>`), so a link in a document, a tab in a workstation, a bundle's home route and the assistant's `open` tool all land on the same thing. The browser's back and forward work everywhere, including inside a workstation tab.

A page kept open across a new release asks for code the server has replaced. The app notices — a view whose code no longer exists — and reloads itself once to come back on the new version; nothing is lost that it has not already saved. If it happens twice in a minute the view says so instead of reloading again, with a **Reload page** button, so a tab can never end up in a reload loop.
