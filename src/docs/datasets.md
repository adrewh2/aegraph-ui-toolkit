# Datasets

A dataset is a table kept as one entity: columns and rows, nothing else. It is the hand-off in the analytics flow — **scene → script → dataset → chart**: a graph scene (Unigraph composed with a filter, a layout and a style; [Unigraph](/docs/explorer)) or the whole project goes into a [script](/docs/scripts), the table the script returns is kept as a dataset, and a [chart](/docs/plots) reads the dataset. A dataset is also just a table: paste CSV into one, or type rows in by hand.

Datasets are entities of type `dataset` (the [file format](/docs/spec) says what one carries) and live under **Analytics › Datasets** in the sidebar, the third stop of the flow. The landing page lists them as cards with their shape and where each came from; a card opens the dataset in a **Datasets** tab of the [Analytics](/analytics) page, at `/analytics/datasets?id=<id>`; **New dataset** (or `/analytics/datasets/new`) makes an empty one and opens it. Like every Analytics tab, a Datasets tab sits in the pane host: split it, name it by double-clicking, right-click it for the saved datasets to open beside it.

## Where a dataset comes from

- **A script.** Under a table a script returned, **Keep as a dataset** writes it as a dataset entity and opens it. A *saved* script's table is that script's dataset: the dataset remembers the script (`source: { scriptId, ranAt }`), and **Rerun script** on the Datasets page — or *Keep as a dataset* after another run — refreshes the rows of that same dataset rather than adding another, keeping the name, description and tags you gave it. An unsaved script's table becomes a plain dataset named after the code's first line.
- **CSV.** **⋯ › Paste CSV…** replaces the dataset's columns and rows with the pasted text (the first line is the header; numbers, booleans and JSON are read, the rest is text). A block of cells copied from a spreadsheet pastes straight into the grid at the cursor, growing the table to fit.
- **A file.** A CSV, TSV, Excel (`.xlsx`) or Parquet file attached to a chat becomes a dataset as the message is sent — a workbook one per sheet with cells — and a text file does when you say it is one and what separates its columns ([Assistant › Attaching files](/docs/assistant)). The dataset remembers the file (`source: { kind: 'file', filename, format, sheet?, importedAt }`), is named after it, and takes the file's kind as its type — a subtype of `dataset`: `dataset:csv`, `dataset:tsv`, `dataset:text`, `dataset:excel` or `dataset:parquet` (CSV text handed to the assistant is a `dataset:csv` too). The Datasets list shows every kind together, each marked with what it was read from; in the Entities tables and the ontology they sit under *Dataset* the way a filter script sits under *Script*. A dataset a script returned, one made from entities or one typed in is a plain `dataset`. Files are read in the browser, nothing leaves the machine, and with limits: 50 MB, 200,000 rows, 500 columns, 5 million cells, 128 million characters of text, and at most 100 sheets of a workbook (name the sheet to read one of a bigger one).
- **By hand.** An empty dataset has three columns and one blank row; add rows and columns and type.
- **Entities.** The Entities table's **Export › Keep as a dataset** writes the rows it shows, in the columns it shows, as a dataset and opens it; the assistant's `dataset {action:'from_entities', selector}` does the same for the entities a selector names over the whole dataset (types, tags, text, field predicates), with every field the types declare as columns — coordinates and other hidden ones too — or just the `columns` asked for. No script in between, so a city's worth of entities is fine. The dataset remembers what it was made from (`source: { kind: 'entities', selector, count, at }`).

## Counting and computed columns

`dataset {action:"from_entities", group_by}` counts instead of listing: one row per value, most first. `group_by: "type"` is every type in the open project with how many entities it has (columns `type`, `label`, `count`); `"tags"` counts each tag once per entity (and the untagged in a row with no tag); a field such as `data.genus` counts its values. Beside fields, `columns` takes computed values — `degree`, `degree.in:cites`, `metric.pagerank`, another dataset's column — so "each entity and how many links it has" is `columns: ["id", "label", "degree"]`.

## A dataset elsewhere

A dataset is not only a grid. A [chart](/docs/plots) can take its rows (**Rows from** in the chart's panel, `dataset` in the spec). And any place a [value reference](/docs/values) goes — a Unigraph colour or size, a filter predicate, a placement axis — reads a dataset's column as `dataset:<id>.<column>`, on the entity its row matches: by the dataset's `id` column, else its `type` column, else its first column. So one table of counts per type becomes a bar chart and a colour scale in Unigraph without copying anything onto the entities:

1. `dataset {action:"from_entities", group_by:"type", name:"Entity counts"}`
2. `plot {action:"save", name:"Counts", spec:{dataset:"<id>", traces:[{kind:"bar", x:"type", y:"count"}]}}`
3. `graph_style {channels:[{scope:"nodes", by:"all", channel:"color", mode:"ranking", attr:{kind:"value", ref:"dataset:<id>.count"}, palette:"viridis"}]}` — in the Style panel, **Color › Ranking › From datasets › Count · Entity counts**.

## Editing

The grid is drawn on a canvas, the way a native spreadsheet is: only the rows in view are painted, the header and the row numbers stay put, and the cursor, the selection and a drag never rebuild the page — a table of a million rows scrolls, selects and edits like one of ten. Every edit is a write to the entity — a cell, a block, rows in or out, a sort — so the project's [versions](/docs/projects) see each change and there is no draft to save; a run of typing lands as one write a few hundred milliseconds after the last key, and every edit is undoable (`⌘Z`, `⌘⇧Z`, or the arrows in the toolbar).

- **Cells.** Click a cell to put the cursor on it; **type to replace** its value, `↵` or `F2` to edit what is there, double-click likewise. `↵` commits and moves down, `Tab` right (`⇧` reverses either), `Esc` drops the edit. While you edit, the arrows move through the text and leave the cell at its edge, as in a spreadsheet: `→` with the caret after the last character commits and moves to the cell on the right, `←` before the first to the cell on the left, and `↑`/`↓` (the editor is one line) to the cell above or below — the cell you land on is selected, ready to type over or `↵` to edit. With `⇧`, `⌘` or `⌥` held the arrows stay in the text, to select or jump within it. `⌫` or `Delete` clears the cell — or the whole selection. What you type is read by the column's **kind** when it has one; without one it reads as typed: `3` is a number, `true` a boolean, `[1,2]` JSON, anything else text (the alignment and the mark in the header then follow what the column's first few thousand values are — declare the kind in the header's menu to fix it).
- **Moving.** Arrows, `Tab`, `Home`/`End` (the row), `⌘Home`/`⌘End` (the table), `Page ↑/↓` (a screen), `⌘+arrow` to the edge of the filled block. `↓` or `↵` on the last row **adds a row** and moves onto it — the way to key rows in one after another; the `+` line under the last row does the same on click. The `+` to the right of the last column **adds a column**, named by the next letter (`d`, `e`… then `aa`); a column pasted in is named the same way, and a header's menu renames it. **Drag either `+`** to add as many rows or columns as the drag covers, or drag it back over the table to take empty rows or columns off the end (the drag stops at the first one holding a value); the count shows by the pointer.
- **Selecting.** `⇧+arrows` or a drag select a block; a row number selects the row, a header the column (drag or `⇧` for several); the corner, or `⌘A`, everything. The toolbar counts the cells; the row numbers and headers of the selection are shaded.
- **Blocks.** `⌘C` copies the selection as tab-separated text (what Excel, Numbers and Sheets paste), `⌘X` cuts, `⌘V` **pastes a block at the cursor**: tab-separated, or CSV, or one column of lines — rows and columns are added to make room, and a single value pasted over a selection fills it. `⌘D` fills down and `⌘R` right from the first row or column of the selection; the small square at the selection's corner drags to fill too.
- **Right-click** a cell for copy, cut, paste, clear, fill, insert or delete the rows of the selection, edit; a row number for insert/clear/delete; a **header** for the column: rename it (the header and a description; the **key** — what scripts and charts name the column by — never changes), sort the rows by it, declare its **kind** (text, number, boolean, date, date & time, URL, JSON), insert, move, clear or delete it. Drag a header's edge to resize the column (double-click the edge to fit it); widths are remembered in this browser.
- **The dataset.** The picker at the top switches between datasets; **⋯** renames, describes, **pastes CSV** (replacing every row and column — undoable), **exports CSV** (the column labels as the header; a cell a spreadsheet would run as a formula is written with a `'` in front, which reading the file takes off again), opens the script that made it, or deletes it.

A dataset in the Entities table opens in the inspector as a read-only preview of its first rows with **Open in Analytics**.

## Over MCP

The `dataset` tool does everything the page does: `{action:"list"}`; `{action:"get", id, offset?, limit?, records?}` (paged; `records: true` returns rows as objects keyed by column); `{action:"create", name, columns, rows}`, `{action:"create", name, csv, delimiter?, header?}` (delimited text: comma unless `delimiter` names another — `tab`, `semicolon`, `pipe`, `whitespace` or the characters themselves — and the first line the header unless `header: false`) or `{action:"create", file, filename, sheet?}` (a whole CSV, TSV, text, Excel or Parquet file as a `data:` URL, read as a chat reads one attached, with the same limits); `{action:"from_script", script}` (run a saved script and keep its table — the same script refreshes the same dataset); `{action:"set", id, cells: [{row, col, value}]}` (cells, read by the column's kind); and the actions *add_rows*, *delete_rows*, *add_column*, *update_column*, *move_column*, *delete_column*, *sort*, *rename*, *open* and *delete* as their names say. Like the page's *New dataset* and *Keep as a dataset*, a dataset the assistant makes (*create*, *from_script*, *from_entities*) opens as soon as it exists — on the Datasets page, or on the Chats page as a tab beside the chat that asked for it; `open: false` makes one without leaving the page you are on. A column is named by its key, its label or its index; indices are 0-based.
